## Why plan 001 was shipped

The run had to pick one plan to implement. Plan 001 was chosen because:

- It is the highest-severity finding with HIGH confidence. `createOrUpdateFile`
  commits to the **default branch** whenever `branch` is omitted, and the old
  gate accepted any branch in the signed repository. One wrong model call, or a
  prompt-injected PR, could commit straight to `main` and skip review. A fork
  PR whose head ref is `main` was worse: the same name in the base repository
  _is_ the default branch.
- Label, PR-edit, summary, reply, and reviewer writes accepted any PR number in
  the repository, so pause/resume and summaries could land on another PR.
- The repository's own audit (`docs/reliability-audit.md`, F2) recorded this
  as an open limit ("does not claim to bind every write to a particular PR or
  branch"), so the fix closes a known gap and reverses no decision.
- The fix is deterministic and lives behind the existing extension approval
  hooks, so Vitest and the typecheck can verify all of it with fixture HTTP and
  no model calls. The new tests fail against the old policy (22 failures) and
  pass with the fix.

Plan 002 is close behind and small. It was not picked because blocking
untrusted commenters changes who can use the bot, which is a product call the
maintainer should make (see its open question).

## Findings considered and rejected

- **GraphQL `reviews(author: "<slug>[bot]")` in `agent/tools/enable-auto-merge.ts:83`
  never matches App reviews**: rejected. A read-only query against a public PR
  showed the `[bot]` form matches the Bot's review and the bare slug returns
  nothing.
- **Installation lookup on every token request (`agent/lib/github.ts:38-52`)**:
  by design. PR #52 removed the cache to recover from reinstallation (audit F1),
  and auth-app still caches tokens.
- **`installationFor` uses raw `fetch` rather than Octokit**: works, is tested,
  and is a style preference with no defect.
- **Merge policy ignores `COMMENTED` reviews when finding each reviewer's latest
  state (`agent/lib/merge-policy.ts:118-124`)**: matches GitHub's review-state
  semantics.
- **Dependency bumps / lint-only cleanups**: baseline is green and no
  critical advisories were in scope. Not worth a plan.
