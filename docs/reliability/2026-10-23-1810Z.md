# Model timeouts: exact incident and GLM route mitigation

Collected October 23, 2026, approximately 18:03–18:10 UTC. This investigation
matches user error `c9cbb9df-132b-4535-9a2d-c7bc2c411c20` to production logs.
The user subsequently authorized disabling a slow route through Chrome and asked
whether slow reasoning was responsible. No application code or deadline changed.

## Outcome

**Verified:** PR Bot aborts individual model calls after 90 seconds. Eve wraps
the resulting `TimeoutError` as `ModelStreamStalledError`, retries, and eventually
parks the failed turn for another user request. This message does not establish
that the provider stopped sending tokens.

**Verified mitigation:** GLM-5.3 on NVIDIA (`z-ai/glm-5.3`) was disabled through
the model detail page in Chrome at approximately 18:10 UTC. Both its row switch
and `In chain` switch changed from on to off. Other NVIDIA models and credentials
were untouched. This is a reversible global router change, affecting every client
using this FreeLLMAPI instance, rather than a PR Bot-only override. The user
authorized the change. Production impact on subsequent review completion remains
unverified.

**Unresolved:** the historical canceled requests cannot be separated into queue,
prefill, reasoning, answer generation, or connection wait from available metadata.
Controlled requests established that GLM could respond quickly at collection time,
including a larger synthetic input; they did not reproduce the production failure.

Repeated operation identities across invocation replay are not independent
completed operations. This trace shows five completed 90-second failures and one
additional model attempt interrupted by the host limit. Failed-call metadata
reports only requested model `auto`; selected-model attribution comes from router
logs with matching times, not from an explicit shared cross-service request ID.

## Router evidence: slowness, stalls, and misleading zeros

The live FreeLLMAPI log closely matches the final retry sequence:
GLM requests start at 17:57:18, 17:58:49, and 18:00:20 UTC; cancellations appear at
17:58:48, 18:00:19, and 18:01:50. Each cancellation states that the upstream was
canceled and the model was not benched. This temporal correlation strongly
implicates the NVIDIA GLM route, although the services lack a shared request ID.

The router separately recorded an actual GLM stream stall at 17:58:59:
**no data for 30,000 ms**, total latency 82,972 ms. Its analytics row had 159 output
tokens. That is evidence of an interruption after partial output on another
request, not proof that the exact incident had the same stream phase.

In the dashboard's 24-hour model sample, GLM showed 190 requests, displayed
success 67.8%, and average latency 42,851 ms. Individual successful GLM requests
near the incident took about 82–89 seconds. These are observational workloads,
not a controlled comparison with another model.

Two important source-backed limitations:

- [The fallback loop](https://github.com/tashfeenahmed/freellmapi/blob/26484157fd15f5fb66f54d3a86f568997ea304de/server/src/lib/fallback-loop.ts)
  explicitly records client cancellation with **zero input and output tokens**,
  then returns without benching the route. Those zeros are placeholders, not
  measurements of whether reasoning or text was generated.
- [Analytics](https://github.com/tashfeenahmed/freellmapi/blob/26484157fd15f5fb66f54d3a86f568997ea304de/server/src/routes/analytics.ts)
  excludes cancellations from the success-rate denominator. Its displayed success
  rate therefore does not measure PR Bot's completion rate under its 90-second
  deadline. The routing page's reliability score of 98 also cannot rebut the
  observed client timeouts.

This creates a verified retry weakness: a slow call can be canceled by PR Bot,
remain unpenalized by the router, and be selected again by the next Eve attempt.
The repeated selection is observed; its upstream queue/reasoning cause is unknown.

## Controlled reasoning check

Playground requests pinned GLM-5.3 through the visible model selector, with default
sampling and reasoning settings. Inputs were synthetic; no repository content or
credentials were placed in prompts. Four preliminary small requests were rejected
by existing cooldown before the route became available.

- Small request asking for `OK`: **2,704 ms** in the UI; browser network timing
  was approximately 2.7 seconds. The SSE response contained 169 estimated input
  tokens, 47 estimated completion tokens, 169 characters of reasoning, and a
  two-character answer. Reported usage was marked estimated.
- Larger request: **72,139 characters**, consisting of 1,200 numbered records
  and an instruction to return the last identifier. It returned `1200` in
  **12,642 ms**, with 136 characters of reasoning stored by the Playground.
  First browser response data arrived after approximately 11.67 seconds.
  The browser ended its fetch after consuming the result; the UI and stored
  conversation confirmed success. A complete SSE body was unavailable for this
  second request, so input-token count and exact per-phase reasoning duration
  were not measured.

These single samples show that neither default GLM reasoning nor a larger simple
input necessarily takes 90 seconds. They do not reproduce tool-heavy review
reasoning, concurrent load, uncached production prefills, or the historical stall.
There was no reasoning-on/off experiment, and no claim that reasoning is ruled out.

## Verification and next checkpoint

`pnpm test -- test/model.test.ts` actually ran the full configured suite:
**134 tests passed in 10 files**, in 12.53 seconds. The existing provider tests
verify cancellation at headers, stalled body, and continuous output, showing that
the total deadline applies even when tokens keep arriving. They do not reproduce
Eve's complete retry/replay sequence; the production trace establishes that
sequence for this incident.

- GLM route mitigation: **released in router UI**, improvement **unverified**.
  Next compare deduplicated failed turns, timeout counts, time to delivered review,
  and quality on subsequent comparable PRs; account for in-flight GLM calls.
- Historical reasoning versus queue/prefill: **unverified**. Next capture only
  metadata at the model streaming boundary: selected route/request identity,
  headers latency, first reasoning/text/tool-call timestamps, last-byte age,
  reasoning/output counts, and abort reason. Never log reasoning or review text.
- Retry/invocation budget: **observed defect**, unresolved. The same invocation
  includes earlier model work, so three fresh 90-second retries need not fit in
  the remaining 300 seconds. Validate through a controlled Eve fixture before
  selecting an aggregate budget or requesting upstream retry controls.
- Reasoning reduction: **unexecuted experiment**. Eve supports native `reasoning`
  configuration, but PR Bot currently leaves it at provider default. Verify the
  configured adapter's mapping and NVIDIA GLM support before a controlled
  default-versus-reduced comparison. Do not assume a generic effort setting
  disables this model's thinking.

No deadline increase, extra retry layer, dependency update, or app deployment was
performed. The earlier observability release is confirmed live, and its retained
model/turn identities enabled this investigation; it did not change model routing.
