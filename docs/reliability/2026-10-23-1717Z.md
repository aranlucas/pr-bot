# Reliability cycle: returned errors and stale review publication

October 23, 2026. Baseline: checkout `a7a0fb7`, Eve 0.82.0, GitHub Tools SDK
1.18.0, Eve extension 0.9.0. This cycle implements the findings from the
[initial production investigation](../reliability-research.md). It adds no new
production sample; the original report retains its collection windows and
coverage limits. Production impact is pending deployment and fresh evidence.

## Changes verified locally

**Returned GitHub errors are now observable.** A native `action.result` hook
recognizes SDK error payloads even when the executor resolves successfully.
It reports `tool.result.failed` using only a catalog code, known tool name,
call ID, and session/turn/step identity. Unknown codes and string errors become
`github_tools.UNKNOWN`. Replayed events for the same call retain the same Sentry
event identity. Normal results, unrelated tools, and already-failed actions do
not create a second error report.

The regression tests call the actual SDK against HTTP 401, 403, 404, and 422
fixtures, then pass its returned JSON through Eve's public hook boundary.
They also cover the rate-limit catalog code and unknown/string error shapes.
The rate-limit payload test does not claim to exercise Octokit throttling timing.
Secret response text and payload fields remain absent from emitted metadata.

**Model identity and turn failure codes survive.** Operation-scoped state keeps
the requested model/provider through worker replacement and includes them on
model completion/failure. A native failed-turn hook preserves the structural
failure code and whether the session is terminal, excluding messages/details.
The old metadata-only turn-failure subscriber is removed to avoid duplicate
reports from the two surfaces.

**Attempt failures, operation failures, terminal failures, and denials are
distinguishable.** Structured logs include `level` and `failureKind`. Model/step
attempts and tool errors are warnings; failed turns and sessions are errors.
Policy denials stay searchable at info level without creating Sentry failure
issues. This changes emitted telemetry; existing Sentry issues are untouched.
Embedded severity does not establish how Vercel will index the new records.

**Review creation has a deterministic freshness gate.** The existing extension's
approval override now requires a current-turn assessment for the signed webhook's
PR and policy version. It refreshes the PR with the native SDK and rejects a
closed/merged PR, moved head, missing/stale assessment, wrong target, cancelled
call, or unreadable current state. Findings and review-only assessments still
permit review publication. After a bot fix, instructions require reassessing the
new head. Mounted-extension tests assert a POST for the assessed head and no POST
for a moved head; other tests cover closed/merged PRs and failed readiness reads.

This local predicate is necessary because the installed GitHub extension has no
built-in current-webhook/assessed-SHA publication policy. GitHub operations remain
in its native executor. No dependency, GitHub wrapper, custom script, or second
coordination store is introduced. The gate does not make the read and later
GitHub write atomic, and it applies to batched review creation rather than all
timeline comments, replies, or file writes.

## Validation

- `pnpm check`: lint, formatting, typecheck, and 134 tests passed in 10 files.
- `eve build --skip-sandbox-prewarm` with synthetic build-only credentials:
  compiled successfully. Sandbox preparation was skipped; this is a compile
  check, not proof of a deployable production snapshot or live webhook behavior.
- The user-level `$eve-reliability` skill passed structural validation and an
  independent offline exercise. It distinguished a recovered retry, a correct
  moved-head denial, and a returned-error publication failure, and declined to
  invent rates without denominators. Its workflow records the next check and
  differentiates local results from production impact.

## Carry-forward status

- Returned-error telemetry, model/provider correlation, turn codes, denial
  classification, and review freshness: **fixed locally**. Next evidence: on the
  released SHA, observe safe returned-error metadata, a recovered attempt versus
  failed-turn distinction, and a current-head review in a disposable PR. Verify
  actual Vercel indexing and Sentry tags. Do not inject failures on production PRs.
- Model-route/deadline tuning: **unverified**. Keep the current route and deadline
  until equivalent review fixtures compare quality, completion, latency, and all
  retry layers. The earlier sample includes successful slow requests, so a lower
  deadline is not automatically an improvement.
- Webhook delivery-key wiring and missing-deployment recovery: **verified source
  gap / observed baseline incident**, unresolved locally. Eve 0.83's published
  changelog does not identify fixes for those specific paths. Reproduce in a
  disposable deployment and request native support; reconcile accepted work before
  redelivery. No recovery or retention setting was changed in this cycle.
- Atomic review/merge head preconditions, ambiguous writes, and summary
  deduplication: **unverified guarantees**. The new gate narrows the review race;
  upstream SDK support and lost-response/replay fixtures remain necessary.
- MCP per-phase deadlines and full behavioral/compaction evals: **unverified**.
  They require a functioning isolated protocol/eval target; current boundary tests
  do not establish those guarantees. Production interactive auth remains disabled.

The next cycle should verify this release's emitted outcomes and returned-error
path before expanding retry or routing behavior. Measure publication success
against deduplicated eligible deliveries with the same release/window; until
that denominator and post-release sample exist, improvement rates are unknown.
