## Change and native API boundary

The installed versions are Eve `0.82.0`, GitHub Tools SDK `1.18.0`, extension
`0.9.0`, and `@octokit/auth-app` `8.3.1`. Inspection of the SDK's exported tool
catalog and presets found no authenticated-App metadata capability. Its public
`createOctokit` client does expose `rest.apps.getAuthenticated()`.
[GitHub documents `GET /app`](https://docs.github.com/en/rest/apps/apps#get-the-authenticated-app)
as returning the App associated with the authenticated credentials.

The small domain helper in `agent/lib/github.ts` uses the existing
`createAppAuth` configuration to authenticate that native API call and validates
the slug with Zod. All three identity checks use the resolved, normalized bot
login. The mention alias remains unchanged. No dependency, generic registry,
cache abstraction, or model-facing identity tool was added.

Only a validated successful login is cached, for the process lifetime. A failed
lookup leaves no cached rejection, so the next call can recover. Concurrent
first calls may repeat this read; it is not a dispatch lock. Changing the App
slug requires a process restart. Identity failures skip automatic dispatch and
deny formal approval, merge, and queue attempts through the existing policy
boundaries. The no-self-merge and current-head controls remain in place.
