## Selected improvement

**Fix the measurement gap before changing more deadlines.** Eve's public native
lifecycle events report final usage, response identity, and duration, but omit
partial output timing on failures. Its metadata-only trace policy is retained.

The existing AI SDK middleware now observes the provider's typed stream with a
native `TransformStream` and `pipeTo`. It emits two structured records per
streaming invocation: start and one settled snapshot. The snapshot includes:

- elapsed time until the provider stream became available;
- first reasoning, answer text, and tool-input arrival;
- partial UTF-16 character counts and last-output/last-part ages;
- requested model, response identity when available, and finish-part observation;
- completed, truncated, interrupted, error, or aborted outcome, with timeout
  versus cancellation when an abort signal is available.

No prompt, reasoning/answer content, tool name/arguments, arbitrary header, or
raw error message is logged. Logs remain in Vercel and do not add another Sentry
issue stream. Each invocation has a fresh diagnostic call ID; use Vercel request
identity and response IDs to correlate with lifecycle records. Replays create a
new call ID and must not be counted as new logical operations automatically.

No dependency, custom script, second GitHub client, additional retry, timeout
change, or Railway configuration change was added. AI SDK's native middleware
is used because Eve's lifecycle surface lacks partial-stream diagnostics; native
Web Streams provide forwarding, backpressure, errors, and cancellation.

## Verification and limits

`pnpm check` passed lint, formatting, type checking, and **140 tests in 11 files**.
Controlled OpenAI-compatible HTTP/SSE fixtures exercise the actual configured
provider and middleware. They verify timed reasoning/text/tool output, timeout
at headers or body, continuously arriving text and reasoning at the deadline,
caller cancellation, partial-output socket failure, in-band provider error, and
consumer cancellation. Output/error propagation and absence of private content
in diagnostics are asserted. Tests use virtual time and mocked network responses;
they do not establish real-provider latency or full Eve retry/replay behavior.

These are SDK output timings rather than raw-byte or upstream-compute timings.
No-output intervals cannot distinguish queueing from prefill, hidden reasoning,
or proxy buffering. Character counts are not token counts. An SDK finish part
does not establish provider protocol integrity or delivered review success;
`interrupted` can include a consumer stopping without a signal. Hard host kills
can leave a start record without a settled snapshot.
